# Module API Contract Register

**Status:** Draft — resource and create/query contracts indexed; command schemas require implementation review

All routes are versioned under `/api/v1` unless SPEC-001 provider endpoints are explicitly delegated to Supabase Auth. JSON dates use ISO-8601; IDs use UUID. `actor_id`, `tenant_id`, role, grant resolution, ownership and lifecycle state are server-derived. Never accept client fields as authority. Every write rechecks active session, membership, Tenant, resource scope, permission, data policy and domain state.

## Shared envelopes and concurrency

Collection response: `{data: [...], next_cursor}`. Resource response: `{data: {...}, meta: {request_id}}`. Writes return canonical resource IDs and versions; `201` for create, `200` for successful commands. `If-Match` carries expected resource version; `Idempotency-Key` is mandatory for retryable commands. Stable errors: `401`, `403`, non-revealing `404`, `409`, `422`, `429`; do not expose another Tenant's identifiers or validation details.

This register is the canonical index of route and field allowlists. Module-specific business constraints and lifecycle remain in the linked Spec. OpenAPI code generation and executable contract validation are implementation work; do not infer those have run from this document.
