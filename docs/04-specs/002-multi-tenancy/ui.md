# SPEC-002 — Multi-Tenancy — UI

**Status:** Draft — platform lifecycle and tenant selection

Platform operations screen is available only to platform-team operators and exposes create, suspend/reactivate, begin termination, quota administration and support status with confirmation/reason. Tenant creation asks only for the organization name, reason and required fields; the identifier is generated automatically, shown as non-editable preview text and never submitted as client-controlled authority. After creation, its creator can generate a first-admin link by entering email and reason. The state can be resumed after reload only through a server query that rechecks creator and platform authorization. The link is shown once for manual sharing; replacing it revokes the prior pending link. The authenticated Tenant workspace displays a basic member list under `membership.view` and a member invitation form. The form filters role presets against the actor's role permissions and Tenant-compatible scopes; this is a UI hint only, and the server rechecks the effective ceiling and explicit deny. Current invitation RPC supports Tenant scope only, so presets containing Portfolio/Project permissions require future resource scope selection/resolution. The form requests e-mail and reason; server denial remains authoritative. It displays the link once for manual copy, states seven-day expiry, and warns that reissue invalidates the previous link. No email is sent. Tenant Admin has no tenant create/suspend/terminate control.

Tenant switcher lists active memberships returned by server; one membership can auto-route, multiple require user choice, none shows no-access guidance. Termination screen shows export requested/building/ready/delivered/validated, 90-day purge deadline, hold exceptions and completion. Never reveal other tenants or expose invitation/export tokens.

Include loading, empty, expired/revoked invite, slug conflict, forbidden, quota, export failed, hold and purge pending states.
Invitation acceptance requires authentication and explains that the confirmed account email must match the invite. Before acceptance, the screen does not reveal the invited email or Tenant. Invalid, expired, revoked, replayed and mismatched-email states use neutral guidance.
